# 客服协同工作功能实现方案

## 📋 需求说明

**核心需求：** 同一个 appid 下的所有客服都能查看和回复同一个用户的消息，实现客服协同工作。

### 当前系统问题

**现状：**
- 客服A回复用户时，只有客服A能看到这条消息
- 客服B看不到客服A发给用户的消息  
- 每个客服只能看到**自己**与用户的对话
- 会话是按"客服-用户"对隔离的

**期望：**
- 客服A、客服B、客服C都能看到与同一个用户的**所有聊天记录**（不管是哪个客服发的）
- 任何客服都能回复这个用户
- 所有客服看到的是**同一个会话**
- 会话是按"用户"分组的，而不是按"客服-用户"对

## 🔍 当前系统分析

### 1. 数据表结构

#### `eb_chat_service_dialogue_record` - 消息详细记录表
```sql
CREATE TABLE eb_chat_service_dialogue_record (
    id INT PRIMARY KEY,
    user_id INT,           -- 发送者的 user_id（可能是客服或用户）
    to_user_id INT,        -- 接收者的 user_id
    msn TEXT,              -- 消息内容
    msn_type INT,          -- 消息类型
    add_time INT,          -- 发送时间
    appid VARCHAR(50),     -- 租户ID
    ...
);
```

**问题：** 这个表记录了所有消息，包括：
- 用户 → 客服A 的消息
- 客服A → 用户 的消息
- 客服B → 用户 的消息

**数据是完整的**，问题在于查询逻辑。

#### `eb_chat_service_record` - 会话摘要表
```sql
CREATE TABLE eb_chat_service_record (
    id INT PRIMARY KEY,
    user_id INT,           -- 会话所有者（客服或用户）
    to_user_id INT,        -- 对方用户ID
    message TEXT,          -- 最新消息摘要
    mssage_num INT,        -- 未读消息数
    update_time INT,       -- 最后更新时间
    appid VARCHAR(50),     -- 租户ID
    ...
);
```

**问题：** 这个表为每个"客服-用户"对创建了独立的会话记录：
- 客服A的视角：`user_id=客服A, to_user_id=用户`
- 客服B的视角：`user_id=客服B, to_user_id=用户`

**这导致了会话隔离！**

## 🛠️ 修改方案

### 方案A：最小改动方案（推荐）

**核心思路：** 保持数据表结构不变，只修改查询和推送逻辑。

#### 修改1：聊天记录查询（允许所有客服查看）

**文件：** `KefuChatService.java`

```java
public Map<String, Object> getChatMessageList(Map<String, Object> filters, Integer kefuId, String currentAppid) {
    // 1. 验证客服身份（确保是同一个appid）
    ChatServiceEntity kefu = chatServiceMapper.selectById(kefuId);
    if (kefu == null || !kefu.getAppid().equals(currentAppid)) {
        throw new CrmChatException("Customer service agent does not exist");
    }

    // 2. 获取对方用户ID
    Integer toUserId = filters.containsKey("to_user_id") && filters.get("to_user_id") != null
        ? Integer.parseInt(filters.get("to_user_id").toString()) : 0;

    QueryWrapper<ChatServiceDialogueRecordEntity> wrapper = new QueryWrapper<>();
    wrapper.eq("appid", currentAppid);

    if (toUserId > 0) {
        // ✅ 修改：查询所有与该用户相关的消息（不限制客服）
        wrapper.and(w -> w
            .eq("user_id", toUserId)
            .or()
            .eq("to_user_id", toUserId)
        );
    } else {
        // 如果没有指定用户，返回空（或者返回所有消息）
        return new HashMap<>();
    }

    wrapper.orderByDesc("add_time");

    // 分页
    Integer page = filters.containsKey("page") ? Integer.parseInt(filters.get("page").toString()) : 1;
    Integer limit = filters.containsKey("limit") ? Integer.parseInt(filters.get("limit").toString()) : 20;

    Page<ChatServiceDialogueRecordEntity> pageObj = new Page<>(page, limit);
    Page<ChatServiceDialogueRecordEntity> pageResult = chatServiceDialogueRecordMapper.selectPage(pageObj, wrapper);

    Map<String, Object> result = new HashMap<>();
    result.put("list", pageResult.getRecords());
    result.put("count", (int) pageResult.getTotal());

    return result;
}
```

#### 修改2：会话列表查询（显示所有用户）

**文件：** `KefuUserService.java`

```java
public List<Map<String, Object>> getRecordList(String appid, Integer kefuUserId, String nickname, String isTourist, String labelId, String groupId) {
    // ✅ 修改：查询所有用户的会话，而不是只查询发给当前客服的
    
    // 方式1：直接查询 eb_chat_user 表，获取所有有聊天记录的用户
    QueryWrapper<ChatUserEntity> userWrapper = new QueryWrapper<>();
    userWrapper.eq("appid", appid);
    userWrapper.eq("is_delete", 0);
    
    if (nickname != null && !nickname.trim().isEmpty()) {
        userWrapper.like("nickname", nickname);
    }
    
    if (isTourist != null && !isTourist.trim().isEmpty()) {
        userWrapper.eq("is_tourist", isTourist);
    }
    
    // 只查询有聊天记录的用户
    userWrapper.exists("SELECT 1 FROM eb_chat_service_dialogue_record WHERE " +
        "(user_id = eb_chat_user.id OR to_user_id = eb_chat_user.id) AND appid = {0}", appid);
    
    List<ChatUserEntity> users = chatUserMapper.selectList(userWrapper);
    
    // 为每个用户构建会话摘要
    return users.stream().map(user -> {
        Map<String, Object> map = new HashMap<>();
        map.put("user_id", user.getId());
        map.put("nickname", user.getNickname());
        map.put("avatar", user.getAvatar());
        map.put("is_tourist", user.getIsTourist());
        map.put("is_kefu", user.getIsKefu() != null ? user.getIsKefu() : 0);
        map.put("online", user.getOnline() != null ? user.getOnline() : 0);
        
        // 查询最新消息
        QueryWrapper<ChatServiceDialogueRecordEntity> msgWrapper = new QueryWrapper<>();
        msgWrapper.eq("appid", appid);
        msgWrapper.and(w -> w.eq("user_id", user.getId()).or().eq("to_user_id", user.getId()));
        msgWrapper.orderByDesc("add_time");
        msgWrapper.last("LIMIT 1");
        
        ChatServiceDialogueRecordEntity lastMsg = chatServiceDialogueRecordMapper.selectOne(msgWrapper);
        if (lastMsg != null) {
            map.put("message", lastMsg.getMsn());
            map.put("message_type", lastMsg.getMsnType());
            map.put("add_time", lastMsg.getAddTime());
        }
        
        // 查询未读数（发给当前客服的未读消息）
        // 这里可以保持原有逻辑，或者改为查询所有未读
        map.put("mssage_num", 0);  // 暂时设为0，后续优化
        
        return map;
    }).collect(Collectors.toList());
}
```

private void broadcastToAllKefu(String appid, Integer senderKefuUserId, Integer chatUserId, Map<String, Object> payload) {
    // 1. 查询同一个appid下的所有在线客服
    QueryWrapper<ChatServiceEntity> wrapper = new QueryWrapper<>();
    wrapper.eq("appid", appid);
    wrapper.eq("status", 1);  // 启用状态
    wrapper.ne("user_id", senderKefuUserId);  // 排除发送者自己
    
    List<ChatServiceEntity> kefuList = chatServiceMapper.selectList(wrapper);
    
    // 2. 推送给每个在线客服
    for (ChatServiceEntity kefu : kefuList) {
        if (kefu.getUserId() != null) {
            boolean isOnline = webSocketPushService.isOnline(appid, kefu.getUserId());
            if (isOnline) {
                // 推送消息更新通知
                webSocketPushService.sendReply(appid, kefu.getUserId(), payload);
            }
        }
    }
}

## ⚠️ 注意事项

### 1. 未读消息数的处理

**问题：** 如果所有客服都能看到同一个用户的消息，未读数如何计算？

**方案A：** 每个客服独立计算未读数
- 客服A看过的消息，对客服B来说仍然是未读
- 需要在 `eb_chat_service_record` 表中保留每个客服的未读数

**方案B：** 共享未读数
- 任何客服查看后，所有客服的未读数都清零
- 需要修改表结构或逻辑

**推荐：** 方案A（每个客服独立计算）

### 2. 客服转接功能

**当前逻辑：** 将用户从客服A转接给客服B
- 客服A的会话记录删除或隐藏
- 客服B接管会话

**修改后：** 所有客服都能看到所有用户
- 转接功能可能需要改为"指派主责客服"
- 或者保留转接，但只是改变"主责客服"标识

### 3. 性能优化

**问题：** 查询所有用户的会话可能导致性能问题

**优化方案：**
- 添加索引：`(appid, user_id)`, `(appid, to_user_id)`
- 分页查询
- 缓存热门会话

## 📝 总结

**核心修改：**
- 查询聊天记录时，不限制客服，查询所有与该用户相关的消息
- 会话列表显示所有用户，而不是按客服分组
- 消息推送时，通知所有在线的客服

**优点：**
- 实现客服协同工作
- 任何客服都能接手用户咨询
- 提高客服效率

**缺点：**
- 可能需要重新设计未读消息数逻辑
- 客服转接功能需要调整
- 需要考虑隐私和权限问题（是否所有客服都应该看到所有对话？）
