DATA FLOW - Admin Login:
-------------------------

1. AdminController
   ↓ (POST /admin/login {account, password})

2. SystemAdminService.login()
   ↓

3. SystemAdminService.verifyLogin()
   ├─ 1. systemAdminMapper.selectOne() → Query DB
   ├─ 2. Status check (is_del, status)
   ├─ 3. passwordService.verifyOrThrow()
   │      ├─ Normalize PHP BCrypt ($2y$ → $2a$)
   │      └─ BCrypt.checkpw() - constant time
   └─ 4. Update login info (last_time, last_ip, login_count)

4. tokenService.generateAdminToken()
   ├─ userId: adminInfo.getId()
   ├─ username: adminInfo.getAccount()
   └─ appid: "10000" (fixed for admin)

5. Build response
   ├─ token
   └─ user_info {id, account, head_pic, real_name}


DATA FLOW - Tenant Login:
--------------------------

1. TenantController
   ↓ (POST /tenant/login {account, password})

2. TenantsService.login()
   ↓

3. TenantsService.verifyLogin()
   ├─ 1. tenantsMapper.selectOne() → Query DB
   ├─ 2. Status check (status)
   ├─ 3. Expiry check (expire_at)
   ├─ 4. passwordService.verifyOrThrow()
   │      ├─ Normalize PHP BCrypt ($2y$ → $2a$)
   │      └─ BCrypt.checkpw() - constant time
   └─ 5. DB auto-update (update_at via trigger)

4. tokenService.generateTenantToken()
   ├─ userId: tenantInfo.getId()
   ├─ username: tenantInfo.getAccount()
   └─ appid: tenantInfo.getAppid() (tenant's appid)

5. Build response
   ├─ token
   └─ user_info {id, account, tenant_name, appid, logo, contacts...}


BENEFITS:
---------

Code Reuse:
- PasswordService: Used by 3 user types (was duplicated 3 times)
- TokenService: Used by 3 user types (was duplicated 3 times)
- ~40% reduction in authentication code

Maintainability:
- BCrypt update → Change 1 file (PasswordService)
- JWT upgrade → Change 2 files (TokenService + JwtUtils)
- Password rules → Change 1 method

Testability:
- Mock PasswordService in unit tests
- Mock TokenService in unit tests
- Test common logic once

Extensibility:
- New user type → Just inject services
- New auth method → Add to PasswordService
- MFA → Add to TokenService

Security:
- Centralized password verification
- Consistent error messages
- Single source of truth for crypto


DESIGN PRINCIPLES:
------------------

1. Composition over Inheritance
   - Flexible: Mix and match services
   - No Java single inheritance limitation
   - Clear dependency graph

2. Single Responsibility
   - PasswordService: Only passwords
   - TokenService: Only tokens
   - Business Services: Only business logic

3. Dependency Injection
   - Constructor injection via @AllArgsConstructor
   - Spring manages lifecycle
   - Easy to test

4. Don't Repeat Yourself (DRY)
   - Password logic: 1 place
   - Token logic: 1 place
   - Business logic: User-specific

5. Open/Closed Principle
   - Open for extension (new user types)
   - Closed for modification (common services stable)
