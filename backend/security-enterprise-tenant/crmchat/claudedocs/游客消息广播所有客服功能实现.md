# 游客消息广播所有客服功能实现

## 📋 需求说明

**需求：** 游客发送消息时，同一个 appid 下的所有在线客服都能实时收到消息推送。

**原有逻辑：**
- ❌ 游客消息只推送给被分配的那个客服（`toUserId`）
- ❌ 其他客服只能看到用户上线通知，看不到消息内容
- ❌ 其他客服需要主动点击用户才能加载历史消息

**新逻辑：**
- ✅ 游客消息推送给所有在线客服
- ✅ 所有客服都能实时看到消息内容
- ✅ 配合之前的客服协同功能，实现完整的多客服协同工作

### 修改2：新增广播方法（第1314-1361行）

**新增方法：**
```java
/**
 * 广播游客消息给所有在线客服（实现客服协同）
 *
 * @param appid 租户ID
 * @param visitorUserId 游客user_id
 * @param payload 消息内容
 */
private void broadcastVisitorMessageToAllKefu(String appid, Integer visitorUserId, Map<String, Object> payload) {
    try {
        // 1. 查询同一个appid下的所有启用状态的客服
        QueryWrapper<ChatServiceEntity> wrapper = new QueryWrapper<>();
        wrapper.eq("appid", appid);
        wrapper.eq("status", 1);  // 只查询启用状态的客服
        wrapper.isNotNull("user_id");  // 必须有user_id

        List<ChatServiceEntity> kefuList = chatServiceMapper.selectList(wrapper);

        log.info("📡 Broadcasting visitor message to {} customer service agents (appid={}, visitor={})",
            kefuList.size(), appid, visitorUserId);

        // 2. 推送给每个在线客服
        int broadcastCount = 0;
        for (ChatServiceEntity kefu : kefuList) {
            Integer kefuUserId = kefu.getUserId();
            if (kefuUserId != null) {
                boolean isOnline = webSocketPushService.isOnline(appid, kefuUserId);
                if (isOnline) {
                    // 推送消息给客服
                    webSocketPushService.sendReply(appid, kefuUserId, payload);
                    broadcastCount++;
                    log.debug("📨 Broadcasted visitor message to kefu: {} (user_id={})", kefu.getNickname(), kefuUserId);
                } else {
                    log.debug("⚠️ Kefu is offline, skipping: {} (user_id={})", kefu.getNickname(), kefuUserId);
                }
            }
        }

        log.info("✅ Successfully broadcasted visitor message to {}/{} online customer service agents",
            broadcastCount, kefuList.size());

    } catch (Exception e) {
        // 广播失败不影响主流程，只记录日志
        log.error("❌ Failed to broadcast visitor message to customer service agents: appid={}, visitor={}, error={}",
            appid, visitorUserId, e.getMessage(), e);
    }
}
```

## 📊 完整的消息流程

### 游客 → 客服（所有客服都能看到）

1. **游客发送消息**
   - API: `POST /api/mobile/service/message`
   - 保存消息到 `chat_service_dialogue_record` 表

2. **广播用户上线状态**
   - 调用 `broadcastUserStatus()`
   - 发送 `user_online` 消息给所有在线客服
   - 所有客服的左侧用户列表更新

3. **延迟100ms**
   - 确保客服端先处理 `user_online` 消息
   - 避免消息到达时找不到对应会话

4. **广播消息内容**
   - 调用 `broadcastVisitorMessageToAllKefu()`
   - 查询所有启用状态的客服
   - 推送 `reply` 消息给所有在线客服
   - 所有客服都能实时看到消息内容

### 客服 → 游客（所有客服都能看到）

1. **客服发送消息**
   - API: `POST /api/kefu/message/send`
   - 保存消息到 `chat_service_dialogue_record` 表

2. **推送给游客**
   - 如果游客在线，推送 `reply` 消息
   - 如果游客离线，推送 `message_num` 未读数

3. **广播给其他客服**
   - 调用 `broadcastToAllKefu()`
   - 推送 `reply` 消息给所有在线客服（排除发送者）
   - 所有客服都能实时看到消息内容

**预期结果：**

**步骤：**
1. 客服A、客服B同时在线
2. 游客连续发送3条消息

**预期结果：**
- ✅ 客服A、B都能实时看到3条消息
- ✅ 消息顺序正确
- ✅ 无需刷新页面

**步骤：**
1. 客服A、客服B同时在线

**预期结果：**
- ✅ 客服A、B都能看到游客的两条消息

## 📈 性能优化建议

### 当前实现

- ✅ 只推送给在线客服（避免无效推送）
- ✅ 广播失败不影响主流程（异常捕获）
- ✅ 详细的日志记录（便于排查问题）

### 可选优化

1. **批量推送优化**

3. **消息去重**
   - 当前：依赖前端 guid 去重

## 🎉 总结

通过这次修改，实现了：

1. **游客消息广播** - 游客发送的消息推送给所有在线客服

- 提升用户体验（更快的响应时间）
