### 5. 用户列表更新逻辑

```javascript
updateUserList(data,op){
  console.log('[updateUserList] 收到更新:', { data, op });

  // 查找用户在列表中的索引
  const userIndex = this.userList.findIndex(item => item.id === data.id);

  if (userIndex !== -1) {
    // 用户已在列表中：移除旧位置，更新后插入顶部
    const existingUser = this.userList[userIndex];

    // 合并所有字段，新数据优先
    const updatedUser = {
      ...existingUser,
      ...data,
      message: data.message !== undefined ? data.message : existingUser.message,
      update_time: data.update_time || data._update_time || existingUser.update_time,
      // ... 其他字段
    };

    this.userList.splice(userIndex, 1);  // 移除旧位置
    this.userList.unshift(updatedUser);  // 插入顶部
  } else if (op) {
    // 用户不在列表中且 op=true：添加到顶部
    this.userList.unshift(data);
  }
}
```

**分析：**
- ✅ 接收到新消息时，会更新用户列表
- ✅ 将有新消息的用户移到列表顶部
- ✅ **逻辑正确**，支持实时更新

methods: {
  // 判断消息是否是客服发送的（包括当前客服和其他客服）
  isKefuMessage(item) {
    // 方法1：检查 user_id 是否在 kefuInfo.user_ids 中（当前客服）
    if (kefuInfo.user_ids.indexOf(item.user_id) !== -1) {
      return true;
    }
    
    // 方法2：检查 is_kefu 字段（其他客服）
    // 需要后端在聊天记录中返回 is_kefu 字段
    if (item.is_kefu === 1) {
      return true;
    }
    
    return false;
  },
  
  // 判断消息是否是其他客服发送的
  isOtherKefu(item) {
    // 不是当前客服，但是客服
    return item.is_kefu === 1 && kefuInfo.user_ids.indexOf(item.user_id) === -1;
  }
}

## ⚠️ 注意事项

### 1. 性能考虑

**问题：** 每条聊天记录都要查询 `chat_user` 表获取 `is_kefu` 字段

**优化方案：**
- 使用 JOIN 查询，一次性获取所有数据
- 缓存 `user_id` → `is_kefu` 的映射关系

### 2. 兼容性

**问题：** 旧的聊天记录可能没有 `is_kefu` 字段

**解决方案：**
- 前端做容错处理：`item.is_kefu === 1` 而不是 `item.is_kefu == true`
- 后端返回时设置默认值：`is_kefu: 0`

### 3. 客服转接功能

**当前逻辑：** 转接后，原客服的会话记录会被删除或隐藏

**修改后：** 所有客服都能看到所有用户，转接功能可能需要调整

**建议：**
- 保留转接功能，但改为"指派主责客服"
- 其他客服仍然能查看和回复，但有一个"主责客服"标识
