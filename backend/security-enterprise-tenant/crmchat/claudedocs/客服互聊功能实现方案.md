# 客服互聊功能实现方案

## 📋 需求说明
同一个 appid 下，客服能够：
1. 查看其他客服的消息
2. 向其他客服发送消息
3. 在会话列表中看到其他客服

## 🔍 当前系统分析

### 数据库设计
```sql
-- eb_chat_user 表（用户表）
CREATE TABLE eb_chat_user (
    id INT PRIMARY KEY,
    nickname VARCHAR(255),
    avatar VARCHAR(255),
    is_kefu TINYINT DEFAULT 0,  -- ⭐ 关键字段：标识是否为客服

-- eb_chat_service_record 表（会话记录表）
CREATE TABLE eb_chat_service_record (
    id INT PRIMARY KEY,

    appid VARCHAR(50),
    ...

```

### 当前逻辑
1. **客服发送消息**：`KefuMessageService.sendMessage()`
   - 验证 `to_user_id` 存在于 `eb_chat_user` 表
   - 保存到 `eb_chat_service_dialogue_record`
   - 更新 `eb_chat_service_record`（双向记录）
   - 通过 WebSocket 推送

2. **客服查询会话列表**：`KefuUserExtensionService.getRecordList()`
   - 查询 `eb_chat_service_record` 表
   - 条件：`to_user_id = 当前客服的user_id`
   - **没有过滤 `is_kefu` 字段**

3. **WebSocket推送**：`WebSocketPushService`
   - 根据 `appid + userId` 查找会话
   - 推送 `reply` 类型消息
   - **不区分用户类型**

### 关键发现
✅ **好消息：** 系统已经支持客服互聊的底层逻辑！
- `eb_chat_user.is_kefu` 字段可以标识客服
- 消息发送和推送逻辑不区分用户类型
- 只需要确保客服在 `eb_chat_user` 表中有记录

❌ **问题：** 客服创建时没有同步创建 `chat_user` 记录

## 💡 实现方案

### 方案1：最小改动方案（推荐）⭐

**核心思路：** 
1. 客服创建/更新时，同步创建/更新 `eb_chat_user` 记录，设置 `is_kefu=1`
2. 客服删除时，同步删除或标记 `eb_chat_user` 记录
3. 前端UI区分显示客服和普通用户

**优点：**
- 改动最小，复用现有逻辑
- 不需要修改数据库结构
- 客服之间的消息和客服-用户消息使用相同的表和逻辑
- WebSocket推送逻辑无需修改

**缺点：**
- `eb_chat_user` 表会包含客服记录（但这是合理的设计）

### 方案2：独立客服聊天表（不推荐）

**核心思路：** 创建独立的客服聊天表

**缺点：**
- 需要创建新表
- 需要修改大量业务逻辑
- 增加系统复杂度
- WebSocket推送需要区分消息来源

## 🛠️ 实施步骤（方案1）

### 步骤1：修改客服创建逻辑

**文件：** `TenantKefuService.java`

**修改点：**
1. `createKefu()` 方法中，创建客服后同步创建 `chat_user` 记录
2. `updateKefu()` 方法中，更新客服后同步更新 `chat_user` 记录
3. `deleteKefu()` 方法中，删除客服后同步删除 `chat_user` 记录

**代码示例：**
```java
@Transactional(rollbackFor = Exception.class)
public ChatServiceEntity createKefu(Map<String, Object> data, String appid) {
    // ... 原有的创建客服逻辑 ...
    
    int result = chatServiceMapper.insert(newKefu);
    if (result <= 0) {
        throw new CrmChatException("Failed to create customer service agent");
    }
    
    // ⭐ 新增：同步创建 chat_user 记录
    syncKefuToChatUser(newKefu, appid);
    
    return newKefu;
}

/**
 * 同步客服信息到 chat_user 表
 */
private void syncKefuToChatUser(ChatServiceEntity kefu, String appid) {
    Integer userId = kefu.getUserId();
    
    if (userId == null) {
        // 如果 user_id 为空，创建新的 chat_user 记录
        ChatUserEntity chatUser = new ChatUserEntity();
        chatUser.setNickname(kefu.getNickname());
        chatUser.setAvatar(kefu.getAvatar());
        chatUser.setPhone(kefu.getPhone());
        chatUser.setAppid(appid);
        chatUser.setIsKefu(1);  // ⭐ 标记为客服
        chatUser.setIsTourist(0);
        chatUser.setOnline(kefu.getOnline() != null ? kefu.getOnline() : 0);
        chatUser.setType(0);  // PC端
        chatUser.setCreateTime(LocalDateTime.now());
        chatUser.setUpdateTime(LocalDateTime.now());
        
        chatUserMapper.insert(chatUser);
        
        // 更新客服的 user_id
        kefu.setUserId(chatUser.getId());
        chatServiceMapper.updateById(kefu);
    } else {
        // 如果 user_id 已存在，更新 chat_user 记录
        ChatUserEntity chatUser = chatUserMapper.selectById(userId);
        if (chatUser != null) {
            chatUser.setNickname(kefu.getNickname());
            chatUser.setAvatar(kefu.getAvatar());
            chatUser.setPhone(kefu.getPhone());
            chatUser.setIsKefu(1);
            chatUser.setOnline(kefu.getOnline() != null ? kefu.getOnline() : 0);
            chatUser.setUpdateTime(LocalDateTime.now());
            chatUserMapper.updateById(chatUser);
        }
    }
}
```

### 步骤3：修改客服删除逻辑

**文件：** `TenantKefuService.java`

```java
@Transactional(rollbackFor = Exception.class)
public void deleteKefu(Integer id, String appid) {
    ChatServiceEntity kefu = chatServiceMapper.selectById(id);
    if (kefu == null) {
        throw new CrmChatException("Customer service agent does not exist");
    }
    
    TenantGuard.ensureOwnedByCurrentTenant(kefu.getAppid(), "Customer service agent does not exist");
    
    // ⭐ 新增：同步删除 chat_user 记录
    if (kefu.getUserId() != null) {
        ChatUserEntity chatUser = chatUserMapper.selectById(kefu.getUserId());
        if (chatUser != null && chatUser.getIsKefu() != null && chatUser.getIsKefu() == 1) {
            // 方式1：物理删除
            chatUserMapper.deleteById(kefu.getUserId());
            
            // 方式2：软删除（推荐）
            // chatUser.setIsDelete(1);
            // chatUserMapper.updateById(chatUser);
        }
    }
    
    // 删除客服记录
    chatServiceMapper.deleteById(id);
}
```

### 步骤4：数据迁移脚本

**目的：** 为现有客服创建 `chat_user` 记录

```sql
-- 为现有客服创建 chat_user 记录
INSERT INTO eb_chat_user (nickname, avatar, phone, appid, is_kefu, is_tourist, online, type, create_time, update_time)
SELECT 
    s.nickname,
    s.avatar,
    s.phone,
    s.appid,
    1 AS is_kefu,
    0 AS is_tourist,
    s.online,
    0 AS type,
    NOW() AS create_time,
    NOW() AS update_time
FROM eb_chat_service s
WHERE s.user_id IS NULL OR s.user_id NOT IN (SELECT id FROM eb_chat_user);

-- 更新客服表的 user_id 字段
UPDATE eb_chat_service s
INNER JOIN eb_chat_user u ON s.nickname = u.nickname AND s.appid = u.appid AND u.is_kefu = 1
SET s.user_id = u.id
WHERE s.user_id IS NULL;
```

### 步骤6：后端返回 is_kefu 字段

**文件：** `KefuUserExtensionService.java`

```java
public List<Map<String, Object>> getRecordList(...) {
    // ... 查询逻辑 ...
    
    List<Map<String, Object>> result = new ArrayList<>();
    for (ChatServiceRecordEntity record : records) {
        Map<String, Object> item = new HashMap<>();
        item.put("id", record.getId());
        item.put("user_id", record.getUserId());
        item.put("to_user_id", record.getToUserId());
        item.put("nickname", record.getNickname());
        item.put("avatar", record.getAvatar());
        item.put("message", record.getMsn());
        item.put("is_tourist", record.getIsTourist());
        item.put("online", record.getOnline());
        
        // ⭐ 新增：查询 is_kefu 字段
        ChatUserEntity chatUser = chatUserMapper.selectById(record.getUserId());
        item.put("is_kefu", chatUser != null && chatUser.getIsKefu() != null ? chatUser.getIsKefu() : 0);
        
        result.add(item);
    }
    
    return result;
}
```

## 🧪 测试场景

### 测试1：客服A向客服B发送消息
1. 客服A登录，查看会话列表
2. 客服A点击客服B的头像（或搜索客服B）
3. 客服A发送消息："你好，我是客服A"
4. 验证：
   - 消息保存到 `eb_chat_service_dialogue_record` 表
   - 客服A的会话列表显示与客服B的对话
   - 客服B的会话列表显示与客服A的对话
   - 客服B实时收到WebSocket推送的消息

### 测试2：客服B回复客服A
1. 客服B收到消息后，点击会话
2. 客服B回复："你好，我是客服B"
3. 验证：
   - 消息保存到数据库
   - 客服A实时收到消息
   - 双方会话列表都更新

### 测试3：客服离线时发送消息
1. 客服B离线
2. 客服A向客服B发送消息
3. 验证：
   - 消息保存到数据库
   - 客服B的未读数增加
   - 客服B上线后能看到未读消息

### 测试4：客服删除后的处理
1. 删除客服B
2. 验证：
   - `eb_chat_user` 表中客服B的记录被删除或标记
   - 客服A的会话列表中客服B的对话仍然存在（历史记录）
   - 客服A无法再向客服B发送新消息

## 📊 数据流程图

```
客服A发送消息给客服B:
1. 前端 → POST /api/kefu/message/send {to_user_id: 客服B的user_id}
2. KefuMessageService.sendMessage()
   ├─ 查询 eb_chat_user 表验证客服B存在 (is_kefu=1)
   ├─ 保存到 eb_chat_service_dialogue_record
   ├─ 更新 eb_chat_service_record (双向)
   └─ WebSocketPushService.sendReply(appid, 客服B的user_id, payload)
3. WebSocket推送给客服B的所有会话
4. 客服B前端实时显示消息
```

## ⚠️ 注意事项

1. **数据一致性**
   - 客服的 `nickname`、`avatar` 等信息在 `eb_chat_service` 和 `eb_chat_user` 两张表中都存在
   - 需要保持同步更新

2. **权限控制**
   - 客服只能与同一 appid 下的其他客服聊天
   - 需要验证 `to_user_id` 的 appid

3. **UI区分**
   - 前端需要明确区分客服和普通用户
   - 可以添加"客服"标识或不同的头像边框

4. **历史数据**
   - 需要运行数据迁移脚本为现有客服创建 `chat_user` 记录

5. **性能优化**
   - 查询会话列表时需要关联 `eb_chat_user` 表获取 `is_kefu` 字段
   - 可以考虑在 `eb_chat_service_record` 表中冗余 `is_kefu` 字段

## 🎯 总结

**最小改动方案的核心：**
1. ✅ 客服创建/更新/删除时同步 `eb_chat_user` 表
2. ✅ 设置 `is_kefu=1` 标识客服身份
3. ✅ 前端UI区分显示客服和普通用户
4. ✅ 运行数据迁移脚本处理历史数据
5. ✅ 无需修改消息发送、接收、WebSocket推送逻辑

**预计工作量：**
- 后端修改：2-3小时
- 数据迁移：30分钟
- 前端UI调整：1-2小时
- 测试：2小时
- **总计：6-8小时**
