# 客服协同工作功能修改总结

## 📋 需求回顾

**原始需求：** 同一个 appid 下的所有客服都能查看和回复同一个用户的消息，客服之间能看见彼此发送的消息。

**核心目标：** 实现客服协同工作，让多个客服能够共同服务同一个用户。

## ✅ 已完成的修改

### 1. 修改聊天记录查询逻辑

**文件：** `KefuChatService.java`

**修改位置：** `getChatMessageList()` 方法（第179-240行）

**修改内容：**

**修改前：**
```java
// 只查询当前客服与用户的对话
wrapper.and(w -> w
    .and(w1 -> w1.eq("user_id", myUserId).eq("to_user_id", toUserId))
    .or(w2 -> w2.eq("user_id", toUserId).eq("to_user_id", myUserId))
);
```

**修改后：**
```java
// 查询所有与该用户相关的消息（不限制客服）
wrapper.and(w -> w
    .eq("user_id", toUserId)
    .or()
    .eq("to_user_id", toUserId)
);
```

**效果：**
- ✅ 所有客服都能看到与同一用户的所有聊天记录
- ✅ 不区分是哪个客服发送的消息
- ✅ 实现真正的协同工作

### 2. 修改会话列表查询逻辑

**文件：** `KefuUserService.java`

**修改位置：** `getRecordList()` 方法（第84-187行）

**修改内容：**

**修改前：**
```java
// 只查询发给当前客服的会话
QueryWrapper<ChatServiceRecordEntity> wrapper = new QueryWrapper<>();
wrapper.eq("appid", appid);
wrapper.eq("to_user_id", kefuUserId);  // 限制为当前客服
```

**修改后：**
```java
// 查询所有有聊天记录的用户（不限制客服）
QueryWrapper<ChatServiceDialogueRecordEntity> dialogueWrapper = new QueryWrapper<>();
dialogueWrapper.eq("appid", appid);
dialogueWrapper.select("DISTINCT user_id, to_user_id");

// 收集所有参与聊天的用户ID
Set<Integer> userIds = new HashSet<>();
for (ChatServiceDialogueRecordEntity record : dialogueRecords) {
    userIds.add(record.getUserId());
    userIds.add(record.getToUserId());
}

// 查询用户信息并构建会话摘要
QueryWrapper<ChatUserEntity> userWrapper = new QueryWrapper<>();
userWrapper.eq("appid", appid);
userWrapper.in("id", userIds);
```

**效果：**
- ✅ 所有客服看到相同的用户列表
- ✅ 会话按用户分组，而不是按"客服-用户"对分组
- ✅ 每个客服仍然保持独立的未读数

### 3. 添加消息广播功能

**文件：** `KefuMessageService.java`

**修改位置：** `sendMessage()` 方法（第215-280行）

**新增内容：**

```java
// 在发送消息后，广播给所有在线的客服
broadcastToAllKefu(appid, kefuRealUserId, toUserId, payload);

/**
 * 广播消息给所有在线的客服（客服协同功能）
 */
private void broadcastToAllKefu(String appid, Integer senderKefuUserId, 
                                Integer chatUserId, Map<String, Object> payload) {
    // 1. 查询同一个appid下的所有启用状态的客服
    QueryWrapper<ChatServiceEntity> wrapper = new QueryWrapper<>();
    wrapper.eq("appid", appid);
    wrapper.eq("status", 1);
    wrapper.ne("user_id", senderKefuUserId);  // 排除发送者
    
    List<ChatServiceEntity> kefuList = chatServiceMapper.selectList(wrapper);
    
    // 2. 推送给每个在线客服
    for (ChatServiceEntity kefu : kefuList) {
        if (kefu.getUserId() != null) {
            boolean isOnline = webSocketPushService.isOnline(appid, kefu.getUserId());
            if (isOnline) {
                webSocketPushService.sendReply(appid, kefu.getUserId(), payload);
            }
        }
    }
}
```

**效果：**
- ✅ 客服A发送消息时，所有在线的客服B、C、D都会收到WebSocket推送
- ✅ 实时更新所有客服的会话列表
- ✅ 广播失败不影响主流程（有异常处理）

## ⚠️ 注意事项

### 1. 未读消息数

**当前实现：** 每个客服独立计算未读数

- 客服A看过的消息，对客服B来说仍然是未读
- 这是合理的设计，因为每个客服需要知道自己是否查看过
- 未读数存储在 `eb_chat_service_record` 表中

**如果需要共享未读数：**
- 需要修改未读数的计算逻辑
- 任何客服查看后，所有客服的未读数都清零
- 需要额外的开发工作

### 2. 客服转接功能

**当前状态：** 客服转接功能可能需要调整

- 原逻辑：将用户从客服A转接给客服B
- 修改后：所有客服都能看到所有用户
- **建议：** 将"转接"改为"指派主责客服"
  - 保留转接功能，但只是改变"主责客服"标识
  - 其他客服仍然能查看和回复

### 3. 性能优化

**潜在问题：** 会话列表查询可能影响性能

**优化建议：**

1. **添加数据库索引：**
   ```sql
   CREATE INDEX idx_dialogue_appid_user 
   ON eb_chat_service_dialogue_record(appid, user_id);
   
   CREATE INDEX idx_dialogue_appid_to_user 
   ON eb_chat_service_dialogue_record(appid, to_user_id);
   ```

2. **添加分页：**
   - 当前会话列表没有分页
   - 如果用户数量很大，建议添加分页功能

3. **缓存优化：**
   - 可以缓存热门会话
   - 使用Redis缓存会话列表

### 4. 权限和隐私

**考虑因素：**
- 是否所有客服都应该看到所有对话？
- 是否需要按部门或权限级别限制？
- 是否需要记录哪个客服查看了哪些对话？

**建议：**
- 如果需要更细粒度的权限控制，可以添加：
  - 客服分组功能
  - 权限级别设置
  - 查看日志记录

### 5. WebSocket推送

**当前实现：**
- 广播给所有在线的客服
- 如果客服数量很多，可能需要优化

**优化建议：**
- 只推送给正在查看该用户会话的客服
- 使用消息队列（如Redis Pub/Sub）实现分布式推送
- 添加推送失败重试机制
