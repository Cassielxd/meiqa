## 🧪 测试场景

### 场景1：客服A向客服B发送消息

#### 步骤：
1. **准备测试数据**
   - 确保有两个客服账号：客服A、客服B
   - 两个客服都已经有关联的 `chat_user` 记录（`is_kefu=1`）

2. **客服A登录**
   ```
   POST /api/tenant/kefu/login
   {
     "account": "kefuA",
     "password": "password123"
   }
   ```
   - 保存返回的 token

3. **客服A查看会话列表**
   ```
   GET /api/kefu/user/record
   Headers: Authorization: Bearer {token}
   ```
   - 验证返回的列表中包含 `is_kefu` 字段
   - 如果客服B之前没有聊天记录，列表中可能看不到客服B

4. **客服A向客服B发送消息**
   ```
   POST /api/kefu/message/send
   Headers: Authorization: Bearer {token}
   Body:
   {
     "to_user_id": 123,  // 客服B的 user_id（从 eb_chat_user 表查询）
     "msn": "你好，我是客服A",
     "msn_type": 1,
     "guid": "unique-guid-12345"
   }
   ```

5. **验证数据库**
   ```sql
   -- 检查消息记录
   SELECT * FROM eb_chat_service_dialogue_record
   WHERE user_id = {客服A的user_id} AND to_user_id = {客服B的user_id}
   ORDER BY id DESC LIMIT 1;
   
   -- 检查会话记录（双向）
   SELECT * FROM eb_chat_service_record
   WHERE (user_id = {客服A的user_id} AND to_user_id = {客服B的user_id})
      OR (user_id = {客服B的user_id} AND to_user_id = {客服A的user_id});
   ```

6. **客服A刷新会话列表**
   ```
   GET /api/kefu/user/record
   ```
   - 验证列表中出现客服B
   - 验证 `is_kefu=1`
   - 验证最新消息内容

#### 预期结果：
- ✅ 消息成功保存到 `eb_chat_service_dialogue_record` 表
- ✅ 会话记录成功保存到 `eb_chat_service_record` 表（双向）
- ✅ 客服A的会话列表显示与客服B的对话
- ✅ 会话列表中 `is_kefu=1`

## 🔍 数据验证SQL

### 检查客服的 chat_user 记录
```sql
SELECT 
    s.id AS service_id,
    s.nickname AS service_nickname,
    s.account,
    s.user_id,
    u.id AS user_id,
    u.nickname AS user_nickname,
    u.is_kefu,
    u.is_tourist,
    u.is_delete
FROM eb_chat_service s
LEFT JOIN eb_chat_user u ON s.user_id = u.id
ORDER BY s.id;
```

### 检查客服之间的消息记录
```sql
-- 查询客服A和客服B之间的所有消息
SELECT 
    d.id,
    d.user_id,
    u1.nickname AS sender_nickname,
    u1.is_kefu AS sender_is_kefu,
    d.to_user_id,
    u2.nickname AS receiver_nickname,
    u2.is_kefu AS receiver_is_kefu,
    d.msn,
    d.type,
    FROM_UNIXTIME(d.add_time) AS send_time
FROM eb_chat_service_dialogue_record d
LEFT JOIN eb_chat_user u1 ON d.user_id = u1.id
LEFT JOIN eb_chat_user u2 ON d.to_user_id = u2.id
WHERE u1.is_kefu = 1 AND u2.is_kefu = 1
ORDER BY d.id DESC;
```

### 检查客服之间的会话记录
```sql
-- 查询所有客服之间的会话
SELECT 
    r.id,
    r.user_id,
    u1.nickname AS owner_nickname,
    u1.is_kefu AS owner_is_kefu,
    r.to_user_id,
    u2.nickname AS peer_nickname,
    u2.is_kefu AS peer_is_kefu,
    r.message,
    r.mssage_num,
    r.online,
    FROM_UNIXTIME(r.update_time) AS last_update
FROM eb_chat_service_record r
LEFT JOIN eb_chat_user u1 ON r.user_id = u1.id
LEFT JOIN eb_chat_user u2 ON r.to_user_id = u2.id
WHERE u1.is_kefu = 1 AND u2.is_kefu = 1
ORDER BY r.update_time DESC;
```

## ⚠️ 常见问题排查

### 问题1：客服发送消息失败，提示"User does not exist"
**原因：** 目标客服没有关联的 `chat_user` 记录

**解决：**
```sql
-- 检查目标客服的 user_id
SELECT id, nickname, user_id FROM eb_chat_service WHERE id = {客服id};

-- 如果 user_id 为 NULL，执行数据迁移脚本
```

### 问题2：会话列表中看不到其他客服
**原因：** 没有聊天记录，或者查询条件过滤了客服

**解决：**
- 先发送一条消息建立聊天记录
- 检查 `is_tourist` 筛选条件是否正确

### 问题3：`is_kefu` 字段始终为 0
**原因：** `chat_user` 记录未正确标记

**解决：**
```sql
-- 更新 is_kefu 字段
UPDATE eb_chat_user u
INNER JOIN eb_chat_service s ON u.id = s.user_id
SET u.is_kefu = 1
WHERE u.is_kefu != 1 OR u.is_kefu IS NULL;
```

### 问题4：WebSocket 推送失败
**原因：** 客服未建立 WebSocket 连接，或连接参数错误

**解决：**
- 检查 WebSocket URL：`ws://host/ws?type=kefu&token={token}&appid={appid}`
- 检查 token 是否有效
- 检查后端日志
