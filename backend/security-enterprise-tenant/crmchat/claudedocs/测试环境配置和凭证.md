### 2025-10-10 修复内容

#### 修复 1: 客服和游客历史消息加载问题 🔥

**问题描述**:
- **客服端**: 页面刷新后，客服自己发送的消息消失，只显示游客消息
- **游客端**: 页面刷新后，所有历史消息都消失

**根本原因**:
1. **JWT token ID 混淆**:
   - JWT token 中存储的是 `chat_service.id` (13)
   - 但消息记录需要使用 `chat_service.user_id` (821)
   - 导致消息存储和查询使用了错误的ID

2. **游客端缺少JWT解析**:
   - 游客端 `/api/mobile/user/record` 接口未从JWT提取userId
   - 导致无法识别当前登录用户，无法查询历史消息

**数据库验证**:
```sql
-- 修复前（错误）
eb_chat_service_dialogue_record:
  id=1: user_id=13 (❌ 使用了chat_service.id) → to_user_id=890

-- 修复后（正确）
eb_chat_service_dialogue_record:
  id=1: user_id=821 (✅ 使用chat_service.user_id) → to_user_id=890
  id=2: user_id=890 → to_user_id=821
```

**修复方案**:

1. **客服端消息发送修复** (`KefuMessageService.java:160-225`):
```java
// 获取客服的真实user_id（不是id）
Integer kefuRealUserId = kefu.getUserId();
if (kefuRealUserId == null) {
    throw new CrmChatException("Customer service user_id does not exist");
}

// 所有消息和会话记录统一使用kefuRealUserId
record.setUserId(kefuRealUserId);  // 使用user_id (821) 而非 id (13)
upsertRecord(appid, toUserId, kefuRealUserId, ...);
upsertRecord(appid, kefuRealUserId, toUserId, ...);
```

2. **游客端历史加载修复** (`MobileServiceController.java:67-73`):
```java
// 从JWT token中提取游客的userId
Long jwtUserId = UserContext.getUserId();
if (jwtUserId != null && jwtUserId > 0) {
    // 传递给Service层作为cookieUid
    requestParams.put("cookieUid", String.valueOf(jwtUserId));
    log.info("[游客历史消息] 从JWT提取userId: {}, appid: {}", jwtUserId, appid);
}
```

**测试验证**:
```bash

  -e "DELETE FROM eb_chat_service_dialogue_record WHERE appid='202509251953426878';"

# 2. 客服发送消息给游客
# 3. 游客发送消息给客服
# 4. 验证数据库记录

# id=2: user_id=890 (游客) → to_user_id=821 (客服user_id) ✅
```

**影响范围**:
- ✅ 客服端刷新后能正确显示自己发送的消息
- ✅ 游客端刷新后能正确加载完整聊天历史

#### 修复 2: 游客消息显示问题

**问题描述**:
- 游客发送的消息显示为客服名
- 应该显示"我"

**原因分析**:
- 乐观更新时消息对象没有 `user_id` 字段
- 判断逻辑 `msg.user_id && userId && (msg.user_id === userId)` 失败
- 默认显示客服名

#### 修复 5: 客服转接功能无响应 🔥

**问题描述**:
- 客服点击转接按钮没有反应
- 转接列表可以正常显示，但执行转接操作时无响应

**根本原因**:
- **前端API配置错误**: `serviceTransfer` 函数使用 `params` 而非 `data` 发送POST请求
- POST请求应该使用 `data` 将参数放在请求体中
- 使用 `params` 会将数据作为URL查询参数发送
- Java后端 `@RequestBody` 无法从URL参数读取数据，导致参数丢失

**错误代码** (`kefu.js:220-226`):
```javascript
// ❌ 错误：使用params发送POST请求
export function serviceTransfer(params) {
    return request({
        url: 'service/transfer',
        method: 'post',
        params,  // ← 错误：POST应该用data
        kefu: true
    });
}
```

**修复方案** (`kefu.js:220-226`):
```javascript
// ✅ 正确：使用data发送POST请求体
export function serviceTransfer(data) {
    return request({
        url: 'service/transfer',
        method: 'post',
        data,    // ← 修复：将参数放在请求体中
        kefu: true
    });
}
```

**Java后端期望** (`KefuServiceExtensionController.java:129`):
```java
@PostMapping("/transfer")
public ApiResult<String> transfer(@RequestBody Map<String, Object> data) {
    // @RequestBody 需要从请求体读取JSON
    Integer kefuToUserId = Integer.parseInt(data.get("kefuToUserId").toString());
    Integer userId = Integer.parseInt(data.get("user_id").toString());
    // ...
}
```
