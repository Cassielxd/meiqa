## 4. 修复内容回顾

### 4.1 WebSocket UserContext修复

#### 修复位置
`io.renren.crmchat.websocket.ChatWebSocketServer`

#### 修复内容
```java
// ✅ 新增 runWithUserContext 方法
private static void runWithUserContext(String appid, int userId, String userType, Runnable action) {
    CrmChatUser user = new CrmChatUser();
    user.setAppid(appid);
    user.setUserId((long) userId);
    user.setUsername(userType + ":" + userId);
    user.setUserType(userType);
    UserContext.setUser(user);
    try {
        action.run();
    } finally {
        UserContext.clear();
    }
}

// ✅ @OnOpen中使用
@OnOpen
public void onOpen(Session session) {
    // ...
    runWithUserContext(identity.appid, identity.userId, identity.userType,
            () -> markUserOnline(holder, true));
}

// ✅ @OnClose中使用
@OnClose
public void onClose(Session session) {
    WebSocketSessionRegistry.SessionHolder holder = WebSocketSessionRegistry.remove(session);
    if (holder != null) {
        runWithUserContext(holder.getAppid(), holder.getUserId(), holder.getUserType(),
                () -> markUserOnline(holder, false));
    }
}
```

#### 影响范围
- WebSocket连接建立时的数据库操作
- WebSocket连接关闭时的数据库操作
- 确保MyBatis租户拦截器能正确获取appid

#### 验证点
- WebSocket连接建立成功
- 用户online状态正确更新
- 不同租户的数据隔离

### 4.3 WebSocket Session Redis持久化

#### 修复位置
`io.renren.crmchat.websocket.WebSocketSessionRegistry`

#### 修复内容
```java
// ✅ 新增Redis持久化
private static void persistSession(SessionHolder holder) {
    RedisUtils redis = redis();
    if (redis == null) return;

    String key = redisKey(holder.getAppid(), holder.getUserId());
    SessionDescriptor descriptor = new SessionDescriptor(
            NODE_ID, holder.getUserType(), holder.isTourist(),
            holder.getServiceId(), System.currentTimeMillis());

    redis.hSet(key, holder.getSession().getId(), descriptor,
               SESSION_META_TTL_SECONDS);
}

// ✅ 新增心跳更新
static void touch(Session session) {
    SessionHolder holder = SESSION_LOOKUP.get(session);
    if (holder != null) {
        persistSession(holder);
    }
}
```

#### 影响范围
- WebSocket Session状态持久化
- 支持多实例部署
- 应用重启时Session恢复

#### 验证点
- Redis中正确存储Session元数据
- ping/pong心跳正常工作
- 应用重启后可以查询之前的在线状态

### 4.4 selectById查询修复

#### 修复位置
`io.renren.crmchat.websocket.ChatWebSocketServer` - `authenticate()` method

#### 修复内容
```java
// ✅ 修复: 使用selectOne + QueryWrapper，明确添加appid条件
case "kefu" -> {
    ChatServiceEntity service = serviceMapper.selectOne(new QueryWrapper<ChatServiceEntity>()
            .eq("id", tokenUserId.intValue())
            .eq("appid", appid));  // ✅ 显式添加appid条件
```

## 6. 常见问题排查

### 6.1 启动失败

#### 问题1: 数据库连接失败

```
错误信息:
Communications link failure
The last packet sent successfully to the server was 0 milliseconds ago.

解决方案:
1. 检查MySQL是否启动: mysql.server status
2. 检查数据库配置: application.yml中的url、username、password
3. 检查数据库是否存在: mysql -u root -p -e "SHOW DATABASES;"
4. 检查防火墙: telnet localhost 3306
```

#### 问题2: Redis连接失败

```
错误信息:
Cannot get Jedis connection; nested exception is redis.clients.jedis.exceptions.JedisConnectionException

解决方案:
1. 检查Redis是否启动: redis-cli ping
2. 如果不使用Redis: 注释掉Redis相关配置
3. WebSocket Session会回退到内存模式（单实例可用）
```

#### 问题3: 端口占用

```
错误信息:
Web server failed to start. Port 20108 was already in use.

解决方案:
1. 查找占用进程: lsof -i :20108
2. 杀死进程: kill -9 <PID>
3. 或修改端口: application.yml中的server.port
```

#### 问题1: CrmChatUser类找不到setUserType方法

```
错误信息:
Cannot resolve method 'setUserType' in 'CrmChatUser'

解决方案:
1. 确认CrmChatUser有userType字段:
   private String userType;

2. 确认使用了Lombok @Data注解:
   @Data
   public class CrmChatUser { ... }

3. IDEA中启用Lombok插件:
   Settings → Plugins → 搜索"Lombok" → Install

4. 重新编译:
   mvn clean compile
```

#### 问题2: runWithUserContext方法未定义

```
错误信息:
Cannot resolve method 'runWithUserContext'

解决方案:
1. 确认ChatWebSocketServer中有此方法定义
2. 方法签名:
   private static void runWithUserContext(String appid, int userId, String userType, Runnable action)

3. 如果缺失，添加方法实现（见上面的修复内容回顾）
```

### 6.3 运行时错误

#### 问题1: NullPointerException in UserContext

```
错误信息:
java.lang.NullPointerException: Cannot invoke "String.equals(Object)" because "appid" is null
at io.renren.crmchat.config.CrmTenantLineHandler.getTenantId

原因:
- UserContext未设置
- 或在finally中被过早清理

排查步骤:
1. 检查AuthenticationFilter是否正确设置UserContext
2. 检查WebSocket是否使用runWithUserContext
3. 添加日志:
   log.info("Current appid: {}", UserContext.getAppid());
```

#### 问题2: WebSocket连接被拒绝

```
错误信息:
WebSocket handshake rejected: invalid token

排查步骤:
1. 检查token是否有效:
   curl http://localhost:20108/api/kefu/login -d '{"account":"...","pwd":"..."}'

2. 检查token格式:
   - 正确: ws://localhost:20108/ws?type=kefu&token=xxx
   - 错误: ws://localhost:20108/ws?type=kefu&token=Bearer xxx

3. 查看服务端日志:
   tail -f logs/spring.log | grep "WebSocket"
```
