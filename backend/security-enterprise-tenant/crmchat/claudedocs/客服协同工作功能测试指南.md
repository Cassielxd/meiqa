# 客服协同工作功能测试指南

## 📋 功能说明

**核心功能：** 同一个 appid 下的所有客服都能查看和回复同一个用户的消息，实现客服协同工作。

### 修改内容

1. **聊天记录查询** - 所有客服都能看到与同一用户的所有消息（不区分是哪个客服发的）
2. **会话列表** - 显示所有有聊天记录的用户，而不是按客服分组
3. **消息推送** - 当任何客服回复用户时，通知所有在线的客服更新会话

## 🔍 数据验证SQL

### 验证聊天记录
```sql
-- 查看与用户200的所有聊天记录
SELECT 
    d.id,
    d.user_id,
    u1.nickname AS sender_nickname,
    u1.is_kefu AS sender_is_kefu,
    d.to_user_id,
    u2.nickname AS receiver_nickname,
    u2.is_kefu AS receiver_is_kefu,
    d.msn,
    FROM_UNIXTIME(d.add_time) AS send_time
FROM eb_chat_service_dialogue_record d
LEFT JOIN eb_chat_user u1 ON d.user_id = u1.id
LEFT JOIN eb_chat_user u2 ON d.to_user_id = u2.id
WHERE (d.user_id = 200 OR d.to_user_id = 200)
  AND d.appid = '202509251953426878'
ORDER BY d.add_time DESC;
```

### 验证会话记录
```sql
-- 查看所有客服的会话记录
SELECT 
    r.id,
    r.user_id,
    u1.nickname AS owner_nickname,
    u1.is_kefu AS owner_is_kefu,
    r.to_user_id,
    u2.nickname AS peer_nickname,
    r.message,
    r.mssage_num,
    FROM_UNIXTIME(r.update_time) AS last_update
FROM eb_chat_service_record r
LEFT JOIN eb_chat_user u1 ON r.user_id = u1.id
LEFT JOIN eb_chat_user u2 ON r.to_user_id = u2.id
WHERE r.appid = '202509251953426878'
  AND (r.user_id = 200 OR r.to_user_id = 200)
ORDER BY r.update_time DESC;
```

## ⚠️ 注意事项

### 1. 未读消息数

**当前实现：** 每个客服独立计算未读数
- 客服A看过的消息，对客服B来说仍然是未读
- 这是合理的设计，因为每个客服需要知道自己是否查看过

**验证方法：**
```sql
-- 查看每个客服的未读数
SELECT 
    user_id,
    to_user_id,
    mssage_num
FROM eb_chat_service_record
WHERE appid = '202509251953426878'
  AND to_user_id = 200;
```

### 2. 性能考虑

**会话列表查询优化：**
- 当前实现会查询所有有聊天记录的用户
- 如果用户数量很大，可能需要添加分页
- 建议添加索引：
  ```sql
  CREATE INDEX idx_dialogue_appid_user ON eb_chat_service_dialogue_record(appid, user_id);
  CREATE INDEX idx_dialogue_appid_to_user ON eb_chat_service_dialogue_record(appid, to_user_id);
  ```

### 3. WebSocket推送

**广播机制：**
- 当客服A发送消息时，会推送给所有在线的客服B、C、D...
- 如果客服数量很多，可能需要优化推送策略
- 当前实现已经做了异常处理，广播失败不影响主流程

## 📝 总结

**核心修改：**
1. `KefuChatService.getChatMessageList()` - 查询所有与用户相关的消息
2. `KefuUserService.getRecordList()` - 显示所有用户，不按客服分组
3. `KefuMessageService.sendMessage()` - 广播给所有在线客服

**优点：**
- ✅ 实现客服协同工作
- ✅ 任何客服都能接手用户咨询
- ✅ 提高客服效率
- ✅ 避免用户重复描述问题

**注意：**
- ⚠️ 需要考虑隐私和权限问题
- ⚠️ 大量客服时需要优化性能
- ⚠️ 可能需要调整客服转接功能的逻辑
